## Q1: Matrix Multiplication — Strassen's vs Traditional

### Objective
Multiply two square matrices (n × n) using the Traditional Method (triple nested loop, O(n³)) and Strassen's Algorithm (divide-and-conquer, 7 multiplications per split), verify the results match, and compare performance across matrix sizes that are powers of 2 (2 through 128).

### Approach
- Traditional method: three nested loops directly compute each output cell as a dot product of a row and a column.
- Strassen's method: each matrix is split into four n/2 × n/2 quadrants; 7 recursive multiplications (instead of the naive 8) are combined with additions/subtractions to reconstruct the product. Base case is a 1×1 matrix (scalar multiply).
- Matrices are generated randomly with integer entries 0–9, and results are verified for exact equality after every run.

### Source Code (`matrix_mult.py`)

```python
def traditional_multiply(A, B):
    n = len(A)
    C = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            total = 0
            for k in range(n):
                total += A[i][k] * B[k][j]
            C[i][j] = total
    return C

def strassen_multiply(A, B):
    n = len(A)
    if n == 1:
        return [[A[0][0] * B[0][0]]]
    a11, a12, a21, a22 = split_matrix(A)
    b11, b12, b21, b22 = split_matrix(B)
    m1 = strassen_multiply(add_matrix(a11, a22), add_matrix(b11, b22))
    m2 = strassen_multiply(add_matrix(a21, a22), b11)
    m3 = strassen_multiply(a11, sub_matrix(b12, b22))
    m4 = strassen_multiply(a22, sub_matrix(b21, b11))
    m5 = strassen_multiply(add_matrix(a11, a12), b22)
    m6 = strassen_multiply(sub_matrix(a21, a11), add_matrix(b11, b12))
    m7 = strassen_multiply(sub_matrix(a12, a22), add_matrix(b21, b22))
    c11 = add_matrix(sub_matrix(add_matrix(m1, m4), m5), m7)
    c12 = add_matrix(m3, m5)
    c21 = add_matrix(m2, m4)
    c22 = add_matrix(sub_matrix(add_matrix(m1, m3), m2), m6)
    return join_matrix(c11, c12, c21, c22)
```

### Analysis / Conclusion

Every trial verified: the Strassen result matched the traditional result exactly for all tested sizes, confirming correctness of the divide-and-conquer implementation.

On measured wall-clock time, however, the Traditional method was consistently faster than Strassen's algorithm at every size tested (2 through 128), despite Strassen's better asymptotic complexity (O(n^2.807) vs O(n^3)). This is expected in a pure Python implementation for three reasons:

- Strassen recurses down to 1×1 base cases, creating a very large number of function calls and small list allocations; Python's per-call/per-list overhead dominates at these small-to-moderate sizes.
- Strassen performs extra matrix additions/subtractions (18 per split) which add constant-factor overhead that a naive triple loop avoids.
- Strassen's crossover point — the size at which its better asymptotic growth rate overcomes its larger constant factor — is typically in the hundreds or low thousands for optimized/compiled implementations, and even higher for interpreted Python; it was not reached within the tested range (n ≤ 128).

In production numerical libraries, Strassen is usually combined with a cutover to the traditional method below a threshold size (e.g. n < 64) precisely to avoid this overhead — confirming why the traditional method wins here.

## Q2: Karatsuba's Algorithm for Large Integer Multiplication

### Objective
Multiply two large integers using the Traditional grade-school method (O(n²)) and Karatsuba's Algorithm (divide-and-conquer, 3 multiplications per split), verify results match, and compare performance from 8 up to 1024 digits.

### Approach
- Integers are represented as digit strings so they can exceed native integer limits, and are padded to equal length and to the next power of 2 as required by the recursive split (padding with leading zeros does not change the value).
- Traditional method: grade-school long multiplication implemented digit-by-digit with carry propagation, operating purely on digit arrays (does not rely on Python's built-in big-int multiply, which is itself sub-quadratic).
- Karatsuba's method: splits each number into high/low halves and reduces 4 sub-multiplications to 3 (z0 = low×low, z2 = high×high, z1 = (low+high)×(low+high) − z2 − z0), recombined via z2·10^(2m) + z1·10^m + z0.

### Source Code (`karatsuba.py`)

```python
def traditional_multiply(x_str, y_str):
    x_digits = [int(d) for d in x_str[::-1]]
    y_digits = [int(d) for d in y_str[::-1]]
    n, m = len(x_digits), len(y_digits)
    result = [0] * (n + m)
    for i in range(n):
        carry = 0
        for j in range(m):
            result[i + j] += x_digits[i] * y_digits[j] + carry
            carry = result[i + j] // 10
            result[i + j] %= 10
        result[i + m] += carry
    while len(result) > 1 and result[-1] == 0:
        result.pop()
    return int("".join(map(str, result[::-1])))

def karatsuba(x, y):
    if x < 10 or y < 10:
        return x * y
    n = max(len(str(x)), len(str(y)))
    m = n // 2
    high1, low1 = divmod(x, 10 ** m)
    high2, low2 = divmod(y, 10 ** m)
    z0 = karatsuba(low1, low2)
    z2 = karatsuba(high1, high2)
    z1 = karatsuba(low1 + high1, low2 + high2) - z2 - z0
    return z2 * 10 ** (2 * m) + z1 * 10 ** m + z0
```

From 128 digits onward, Karatsuba pulls ahead and the gap widens steadily — by 1024 digits Karatsuba is roughly 4× faster than the traditional method.

This matches theory: Traditional multiplication is T(n) = O(n²), while Karatsuba is T(n) = 3T(n/2) + O(n) = O(n^log₂(3)) ≈ O(n^1.585). The crossover here (≈128 digits) is reachable within realistic input sizes, in contrast to Q1's Strassen algorithm, because Karatsuba's base case (single-digit multiply) is reached with far fewer recursive levels and less overhead per split than Strassen's matrix-quadrant splitting.

## Q3: Binary Search vs Ternary Search (Menu-Driven Program)

### Objective
Implement a menu-driven program to search a sorted array of n integers using Binary Search and Ternary Search, record step/frequency (comparison) counts, and compare them for best and worst cases, explaining the result via their recurrence relations: T(n) = T(n/2) + O(1) for binary search vs T(n) = T(n/3) + O(1) for ternary search.

### Approach
- Binary Search: at each step, compares the key against the middle element; narrows to the left or right half. Comparisons are counted per key-check performed.
- Ternary Search: at each step, divides the range into three parts using two midpoints (mid1, mid2); narrows to one of three sub-ranges. Comparisons are counted per key-check performed.
- Best case: the key is found on the first probe (2 comparisons for binary; as few as 1–2 for ternary).
- Worst case: the key is absent, forcing the search to narrow all the way down before concluding "not found".

### Menu
1. Generate n sorted random numbers → Array
2. Display Array
3. Search for a key using Binary Search
4. Search for a key using Ternary Search
5. Step/frequency count for best case
6. Step/frequency count for worst case
7. Step/frequency count comparison table across increasing n

### Source Code (`search.py` — core routines)

```python
def binary_search(arr, key):
    lo, hi = 0, len(arr) - 1
    comparisons = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        comparisons += 1
        if arr[mid] == key:
            return mid, comparisons
        comparisons += 1
        if arr[mid] < key:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1, comparisons

def ternary_search(arr, key):
    lo, hi = 0, len(arr) - 1
    comparisons = 0
    while lo <= hi:
        mid1 = lo + (hi - lo) // 3
        mid2 = hi - (hi - lo) // 3
        comparisons += 1
        if arr[mid1] == key:
            return mid1, comparisons
        comparisons += 1
        if arr[mid2] == key:
            return mid2, comparisons
        comparisons += 1
        if key < arr[mid1]:
            hi = mid1 - 1
        else:
            comparisons += 1
            if key > arr[mid2]:
                lo = mid2 + 1
            else:
                lo, hi = mid1 + 1, mid2 - 1
    return -1, comparisons
```

### Analysis / Conclusion

Across every array size tested, Binary Search used fewer or equal comparisons than Ternary Search in the worst case, and the gap widens as n grows (28 vs 36 comparisons at n = 10,000).

This is explained directly by the recurrence relations. Binary Search satisfies T(n) = T(n/2) + O(1), giving T(n) = O(log₂ n), and each level costs at most 2 comparisons. Ternary Search satisfies T(n) = T(n/3) + O(1), giving T(n) = O(log₃ n) — fewer levels of recursion — but each level costs up to 4 comparisons (two midpoints, each possibly compared twice).

Quantitatively: log₂(n) / log₃(n) = log₃(2) ≈ 0.631, so ternary search needs about 63% as many levels as binary search. But it does roughly twice the comparison work per level. Net effect: 4 × log₃(n) ≈ 2.52 × log₂(n), i.e. ternary search performs more total comparisons than binary search, even though it has fewer recursive levels. The measured data (worst-case ratio of about 1.29–1.33 at large n) is consistent with this — binary search's cheaper per-level cost outweighs its extra levels, so binary search remains the more efficient choice for single-key search despite ternary search's smaller recursion depth.
